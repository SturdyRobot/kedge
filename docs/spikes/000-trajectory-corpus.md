# Spike 000 — Is there a trajectory corpus to learn from?

**Date:** 2026-07-25
**Timebox:** 20 minutes
**Verdict:** **PIVOT** — the plan as handed to us is inverted.

## Why this spike ran first

The Forge proposal's thesis is:

> Can the runtime learn reusable capabilities from its own successful executions?

Every downstream component — observer, distiller, compiler, registry — consumes
*recorded successful executions*. Before designing any of them, the cheapest
possible question is whether those executions exist.

The proposal put the benchmark at issue **7 of 8**. `WORKFLOW.md` principle 1
says risk order beats feature order, and stage 2 says a plan that puts the
core-risk measurement in the last phase has the plan inverted. So: measure.

## Method

Locate the ledger kedge actually writes to, and count what is in it.

```sh
find ~ -name "kedge.sqlite"          # -> /Users/noelwork/Documents/kedge/kedge.sqlite
echo "$KEDGE_LEDGER_PATH"            # -> unset, so the default ./kedge.sqlite applies
sqlite3 kedge.sqlite ".tables"
for t in compactions events runs steps; do
  sqlite3 kedge.sqlite "select count(*) from $t"
done
```

## Result

| Table | Rows |

The file exists (32 KB, schema applied, dated 2026-07-24). It has never

Also absent, checked in the same pass:

- no `docs/` at all before this spike created one.

## Interpretation

The corpus is not small. It is **empty**. That is a categorical difference:

- A small corpus is a *quality* risk — you can measure what you have and decide
  whether it generalizes.
- An empty corpus is a *bootstrapping* risk — there is nothing to measure, and
  every metric downstream of it is unmeasurable rather than merely uncertain.

Three consequences for the plan:

1. **Issue #2 (trajectory → skill candidate) is blocked**, not merely
   unstarted. It has no input.
2. **Issue #7 (build a 20–30 task benchmark) is not the seventh task. It is the
   first.** The benchmark is not how Forge gets *graded* — it is how Forge gets
   *fed*. It is the trajectory generator.
3. Any headline number of the `54% → 76%` shape is currently unmeasurable in
   both directions. There is no baseline, so there is nothing to improve on and
   nothing to regress against.

## What this does *not* say

It does not say Forge is a bad idea, and it does not invalidate the research
framing. It says the first slice is the benchmark, and that the benchmark's
reference solver should be **deterministic and scripted, not an LLM** — a
corpus generated by a scripted solver costs nothing per run, is reproducible,
and is exactly what the next spike (repeated structure) needs. The LLM enters
only at generalization, several slices later.
